# 桌游小馆 / Board Game Club

一个中英双语桌游网站，包含德州扑克、卡坦岛基础版与航海家十三张地图（默认／随机）、五子棋、中国象棋。

## 上传 GitHub

1. 解压 `board-game-club-github.zip`。
2. 将解压后的**所有文件**上传到现有仓库 `NIU-55383/holdem-table-online` 的根目录，覆盖同名文件。不要只上传 ZIP，不要再套一层文件夹。
3. 提交后，现有 Render 服务会按照原来的自动部署设置更新。保留 `render.yaml` 中的服务名称。
4. Render 构建命令仍为 `npm install`，启动命令仍为 `npm start`。新依赖会自动安装。
5. 部署完成后刷新网站。首页应显示“桌游小馆”，并有德州扑克、卡坦岛、五子棋、中国象棋四个入口。

所有浏览器资源都随代码包提供，棋盘图形不依赖外部图片 CDN。服务器需要 Node.js 20 或更新版本；浏览器推荐当前 Chrome、Edge 或 Safari。

### 手机加载与同步

- 卡坦岛保留全部原有图案、颜色和布局；地形、资源卡、房屋和经典棋子的原始 SVG 图案直接内嵌在页面中，避免额外图形请求失败时整批图案消失。大厅和其他游戏仍兼容原图形文件。
- 棋盘与操作提示未变化时，聊天、在线状态等同步不再重建整个棋盘。卡坦岛 WebSocket 支持压缩较大的状态消息，旧客户端仍可不压缩连接；不改变游戏规则或隐藏信息权限。
- 若修改 `catan-art.svg`，必须同步 `catan.html` 的 `catanSprite` 内嵌图案，符号 ID 使用 `catan-art-` 前缀；`ui-test.js` 会逐项核对图案一致，并阻断外部图形请求测试卡坦岛显示。
- 这些改动需要同时更新前端文件与 `catan-server.js`，提交推送后等待 Render 部署成功。服务器重启会清空内存中的旧房间，请在当前对局结束后更新并重新开房。

## 本地运行

```sh
npm install
npm start
```

打开 `http://127.0.0.1:8002/`。多人联机需要运行 Node 服务器，直接双击 HTML 不能提供房间服务。Render 部署后，好友使用同一个公开网址与房间号加入，不需要在同一 Wi-Fi。

## 德州扑克

保留原来的 2–8 人牌桌、机器人、练习模式、聊天、概率计算和视频回放。已有的玩家视角与上帝视角回放也保留。

## 统一玩家界面

- 所有游戏都可点击其他玩家或机器人的头像，发送送花、泼水、比心、鼓掌、干杯、好运六种互动。自己和同房玩家都能看到约 2.4 秒的小表情；不影响游戏回合、AI 思考或牌局记录。自己的头像仍打开头像编辑器。每位玩家发送间隔至少 1.2 秒，重连不重播旧互动。
- 聊天气泡按文字长短收缩，长消息限制宽度与高度，不再占满玩家信息整行；完整内容保留在聊天记录中。
- 玩家头像可上传照片、主动点击拍照，或输入一个 emoji；未设置时显示名字首字。在名字旁边或房间内点击自己的头像即可更换，取消不会保存修改。
- 照片在本机居中裁成 128 × 128 的小头像并重新编码为 JPEG（去除原图元数据）后，才同步给房间中的其他玩家；不会上传原图。支持 10 MB 以内的 JPG、PNG 和 WebP。手机拍照取决于设备和浏览器支持，电脑通常打开文件选择器。
- 头像偏好保存在当前浏览器，同一网址下的卡坦岛和德扑共用；服务器持续运行时，重连可恢复房间头像。机器人入座时随机使用统一画风的表情图案或名字首字，不再使用固定人物肖像。
- 卡坦岛、德扑及后续新增游戏共用 `game-ui.js`、`game-ui.css` 的头像状态点：左下角，在线绿色，离线灰色。
- 所有游戏的送花、泼水、比心、鼓掌、干杯和好运都有对应短音效，由 `game-audio.js` 本地合成。收到确认的互动时播放一次，静音仍保留表情；菜单喇叭可开关声音，卡坦岛同时沿用现有音效开关与音量。首次点击、触摸或键盘操作解锁声音，后台与未解锁时不补播，重复事件不重播。新增游戏须在 `game-ui.js` 前加载 `game-audio.js`。
- 状态由真实连接决定，不随是否轮到自己、弃牌或托管而改变；正常运行的机器人和本地单人玩家按在线显示。

## 房主与中途补位

- 德扑、卡坦岛（含航海家）、五子棋、中国象棋共用「房间管理 / Manage room」入口，位于原房间工具栏，图标为两个人。
- 房主可以向在线真人提出转让；对方同意后才生效。其他玩家也可申请成为房主，由现任房主同意或拒绝。
- 房主断线后，按约定号位顺时针寻找下一位在线真人接任，跳过机器人和离线玩家；旧房主重连不会自动取回权限。突然断网需要心跳检测确认，通常在一分钟内，不是切换网络瞬间完成。
- 开局后，房主可移除其他玩家（含机器人），需要再次确认。位置保留为空位，整局暂停；机器人、游戏操作和自动下一手都停止，但聊天、头像互动、管理仍可使用。
- 房主可为指定空位补机器人；新的真人通过房间号加入会自动补第一个空位。接手者继承该座位的棋局、手牌、资源或筹码，不重新开局。多个空位必须全部补齐才继续。
- 被移出者回到加入界面，旧连接的房间权限失效，不会自动抢回座位；本人仍可重新输入房间号加入，前提是仍有空位。本网站沿用房间号加入，不另设密码。
- 所有游戏默认关闭超时托管。只有当前房主能在「房间管理」勾选「全员两分钟未操作时自动托管」，其他玩家可查看、不能修改。开启后，需要作出决定的在线真人 120 秒未操作才托管，最后 20 秒提醒。房主转让、重连及补位沿用房间设置；补位者不继承旧人的托管状态。关闭时清除全员计时并停止因超时触发的托管，但不打断玩家主动开启的托管。
- 所有人仍可主动点「立即托管」或「取消托管」，无需房主开启超时选项。有效游戏操作或「我在，继续操作」会重置计时；聊天、头像、表情不重置；等别人操作、断线及空位暂停期间不计时。断线或离开本身不触发自动代操作或弃牌，等待本人返回或由房主移除补位。房间超时选项开启时，取消个人托管后重新开始当前操作期限。
- 所有服务端使用 `room-control.js` 校验当前成员和房主权限，前端通过共享 `BoardGameUI.mountRoomControl` 显示控制和提醒。此功能需要同时更新前后端并重启服务器。
- 游戏结束提示使用真实赢家姓名和中英双语，例如 `Laura 胜利 / Laura wins`。
- 新增游戏时遵循 `AGENTS.md` 中的共享 UI 规范。

## 卡坦岛

- 每局地图上沿右侧显示金色奖杯与「胜利目标 / Target」：读取当前对局所需分数，基础版 10 分、扬帆出海与穿越荒漠 14 分、四岛群岛 13 分、未知海域 12 分。默认／随机地图一致，重连后保留，未来地图沿用服务器目标分数。
- 开房前展开「棋子外观 / Piece skins」可选择 4 款强盗、3 款海盗。经典默认图案不变，中间两款强盗使用兜帽和头巾蒙面插画。基础版只显示强盗选项；航海家同时显示海盗。选择会用于预览，并随房间同步，重连与再来一局保留。浏览器记住上次选择，加入好友房间则以房主的房间设置为准；只改变外观，不改变规则。
- 3–4 人基础版；真人和机器人可以混合，填满机器人即可单人游玩。
- 开局前可选择自己的号位：空位直接入座，与机器人直接换座，与真人换座须对方同意；可拒绝或取消申请。三人房开放 1–3 号位，四人房开放 1–4 号位，全部座位坐满且没有待处理的换座申请时才可开局。只玩三人时创建三人房。
- 房主权限跟随本人，与号位无关。换座不会转移房主权限或交换头像；刷新、重连保留号位。开局后锁定座位顺序，头像旁显示号位；离线后的房主转交规则维持不变。
- 随机地形和数字分布；相邻地块不会同时出现 6/8。
- 从 1 号位开始按商定的座位顺序建造第一组村庄与道路，第二组逆序建造。房主不是固定先手；再来一局沿用号位。
- 掷骰生产、资源库存、距离限制、建造费用与棋子数量限制。
- 每人上限为 5 个村庄、4 座城市、15 条道路，航海家另有 15 艘船。满额按钮保留灰色外观，点击后在操作区下方显示双语原因，不发送非法建设操作。村庄升级为城市会收回村庄棋子；船满额仍可按规则移动旧船。
- 强盗、7 点弃牌、随机偷取、城市、发展卡、最长道路、最大骑士团、10 分胜利。
- 移动强盗时，空心圆标出合法地块。需要选择偷取对象时，直接点击强盗周围发光的对手村庄或城市；不显示名字选择按钮，无需再次确认。只有一名可偷对象时自动偷取。
- 4:1 银行、3:1 港口、2:1 专用港口与玩家间资源交易。机器人会评估收到的交易。
- 收到面向自己的玩家交易时，右上方显示紧凑金色提示并响一次交易提示音，点击“查看”跳到高亮交易栏。面向全员的交易通知所有接收者；不通知发起人、未被邀请者或已拒绝者。回应、撤回或回合结束后提示自动消失，聊天与重连不重播旧音效。
- 卡坦岛右上角喇叭按钮可开关音效，选择保存在本机浏览器。建船是扬帆、木船与水声，村庄为木槌，城市为重建造与金属声，道路为铺路声；强盗、海盗、垄断、丰收、道路卡、掷骰、交易成功和胜利各有不同短音效，部分选择按钮有轻点声。所有声音均为本地 Web Audio 合成，无人声、文字播报或外部音频下载。浏览器首次点击或键盘操作后解锁声音；静音、后台与断线时停止，不排队补播。动作音效依据服务器确认后的公开事件，不暴露未打出的发展卡。
- 玩家交易可以向所有玩家报价，或指定一名玩家（含机器人）；只有指定对象能回应，向所有人报价也只会与第一位接受者完成一次交换。
- 玩家交易以卡牌点选：点资源图标添加一张，点下方已选卡牌移除一张；付出与换取并排展示，多张自动换行，每次重新打开交易均从空白开始，不继承上次数量。
- 弃牌同时展示保留手牌和待弃牌，点击卡牌在两栏之间移动；选够规定数量后才能确认，多张自动换行，长手牌只在各自栏目内滚动。
- 新聊天会在发送者头像旁显示约 5 秒的气泡（长消息最多 10 秒），同一玩家连续发言更新自己的气泡，聊天记录仍保留；按玩家编号识别同名玩家，刷新或重连不重播历史消息。
- 报价中逐人显示等待回应、已拒绝或未参与，并同步给所有玩家；报价结束后不再显示等待状态。
- 机器人会考虑产出概率、资源覆盖、扩张位置、港口、升级城市和公开对手分数。交易会围绕下一步建造需求，保护关键资源组合，并比较银行与港口的兑换成本；对接近胜利的玩家更谨慎，公开分数达到 8 分时拒绝交易。AI 只依据公开分数和发展卡总数判断对手威胁，不读取其他玩家的隐藏资源明细或发展卡类型。
- 可以本人主动托管，或由房主开启全员两分钟超时托管；断线不触发 30 秒接管。同一浏览器标签页刷新可恢复原座位。
- 棋盘支持双指捏合缩放（1–3 倍），放大后可拖动，缩回原大小自动归位；原大小下单指仍可上下滚页。电脑触控板捏合或 Ctrl + 滚轮也可缩放，放大后用鼠标拖动。移除了加减按钮，手势不会误触建造。
- 点击可用位置直接建造村庄、城市、道路或船，无需再次确认。卡坦岛不含 5–6 人扩展或城市与骑士扩展。
- 手机端使用紧凑棋盘、资源栏和操作区；银行库存默认展开，直接显示五种资源与发展卡余量，仍可手动收起。聊天和对局记录默认折叠。建造费用可通过顶部规则按钮查看。
- 买不了发展卡时仍可点击按钮查看原因：售罄、缺少的资源、未掷骰、初始放置或其他待完成操作；售罄也显示在按钮和银行栏。银行不足导致少领资源时，只向受影响玩家显示应领与实领数量，覆盖多人分配不足、单人部分发放、金矿、丰收和击退海盗奖励；可关闭，重复同步和重连不重弹。银行交易及金矿/丰收选牌时点到空库存，也会说明缺少哪种资源。需部署更新后的服务器。
- 基础版开房页提供站内双语规则弹窗，切换到基础版时也会打开。按获胜目标、起始放置、回合资源、建造费用与棋子上限、强盗、交易、发展卡和奖励分组；房间与对局内可随时重看。基础规则、航海规则和全部地图规则统一按手机可用屏幕宽高显示，中英文自动换行，正文可触摸滚动到末尾；标题、关闭键及“已阅读”按钮固定可见，横竖屏切换也不会截断右侧文字，不影响游戏状态。
- 自己的资源手牌按种类逐张排列，发展卡也逐张显示，牌多时自动换到下一行。操作区下方显示所有玩家的头像、颜色、分数、资源卡数、发展卡数、已用骑士、已建道路总数和最长道路长度，不公开对手的隐藏牌面。
- 最长道路列直接显示服务器计分使用的连续路线长度：每段最多经过一次，允许闭环，分叉和互不相连的道路不累加；对手的村庄或城市会截断路线。长度不足 5 也照常显示，但不颁发最长道路奖；奖项持有人高亮并显示 +2 VP，平手沿用原持有人。
- 发展卡使用统一插画风格和独立图案：胜利点奖杯、丰收篮、道路路标、垄断资源牌，以及骑士。标准牌堆共 25 张：骑士 14、胜利点 5、道路建设 2、丰收 2、垄断 2；海盗巢穴等剧本的例外在规则中单独列明。
- 所有资源数量选择均使用卡牌点选，不再填数字或使用上下箭头。丰收和金矿点上方资源添加，点下方已选卡牌移除，选满后确认；受实时银行库存限制。垄断只选一种资源，点另一种可直接切换，不受银行库存限制。每次重新打开从空白开始，保留交易和弃牌的点牌方式。
- 丰收卡在确认领取资源前可撤回，选择界面和资源弹窗都有撤回按钮。道路卡在放下第一条道路或第一艘船前也可撤回；切换道路/船模式不算放置。撤回后归还原卡，不占用本回合的发展卡次数，恢复原来的掷骰或行动阶段，重连后仍可撤回。一旦确认丰收资源或放下第一段道路/船则不可撤回；骑士和垄断卡不提供此权限。基础版、全部航海地图及联机共用此行为，需要更新服务器代码后重新部署。
- 玩家资源卡和发展卡总数变化时，对应数量下方显示约 3.5 秒的增减提示；只使用公开总数，不显示对手牌型。首次进入、重连和重新开局不会把已有牌误报为新增。

- 十三张地图统一提供“默认地图 / Default”和“随机地图 / Random”。默认布局以提供的中文版规则照片为准；原书只有空白框架的“新世界”使用固定种子生成一张默认示例，并在规则中标注。房间创建时生成地形；重连不换图，再来一局重新生成随机地图。开房页的随机预览是布局样例，具体房间以创建后的地图为准。
- 扬帆出海：主岛与小岛分别随机，小岛框内的海洋也参与洗匀；6/8 不相邻。四岛群岛：保持四岛外形，森林和牧场不配 2、3、11、12。未知海域：保留已知岛屿与迷雾位置，允许红色 6/8 相邻。穿越荒漠：主岛与外地分开洗匀，三块沙漠不移动，6/8 不相邻且不放金矿。各图港口种类在原港口位置洗匀，保留数量与间距。
- 未知海域的 12 块地形与 10 枚数字分开洗匀，即使默认模式也如此。修路、造船或移船到达未知格旁的交叉点立即翻开地形，陆地再放数字并领取一张对应资源；海洋不发资源，金矿用资源点选器任选一张。牌堆仅在服务器保存，客户端与机器人均不提前知道；新发现地块随后正常生产，金矿选择完成后恢复原行动阶段。
- 未知海域没有登岛奖励，12 分获胜；穿越荒漠把沙漠另一侧与三座小岛计作四处独立外地，每人每处首次建村 +2 分，最多 +8，14 分获胜。沙漠另一侧虽与主岛物理相连，但奖励区域独立，不能初始放村庄。
- 世外部落：船到指定海岸领取一次性的胜利点、发展卡或海港。行动发展卡仍须等自己的下一回合（胜利点卡立即计分）；海港须立即移到自己沿海建筑旁的合法海岸，不得与其他港口共用交叉点，仅无合法位置时暂存。外岛不生产、不准建村，中央不再画资源图标。沿海礼物分别显示 +1、发展卡、资源 2:1 或通用 3:1，连线指向领取边；外岛、礼物及海盗均可点击或用键盘打开只读解释，含规则预览图。离开的强盗不能返回外岛。随机时主岛最右三格避开 5、6、8、9。
- 布匹贸易：八个村落各五匹布、公库十匹；首次船路连接和相应掷骰产出布匹，两匹计一分。第三个初始村庄才发资源，连接村落的航线不能移动，不颁发最长商路。海盗可偷资源或布匹；村落有布者少于四个时按分数、再按布匹结算。
- 海盗巢穴：每人一条不分叉航线，途经自己的补给点攻击堡垒。骑士改装战舰，仍受每回合最多打出一张行动类发展卡的限制；每次掷骰先按较小骰点巡航和袭击，再生产或执行七点。败者随机弃资源，胜者点选一张奖励；攻堡一次即结束回合。没有强盗和两大奖，三人移除五张胜利点卡，四人将其作为骑士。未收复的堡垒也占用一枚村庄棋子。随机模式只洗海港，不改变地形、数字、起始位置和巡航路线。
- 卡坦奇观：五张独占奇观牌、各四层，按照片列明资格与每层五张资源。每人只能认领一个，须留有一艘船放在奇观牌上作为标记，此船占用十五艘库存。可一回合建多层；第四层完成即赢，或者达到十分且层数严格高于全部对手。外岛每建一个村庄额外一分。只用强盗，保留最长商路与最大骑士团。大教堂按照片为一座城市和六分，巨像为海港及连续五段商路。
- 新世界：二十三块资源地、十九块海洋，没有沙漠或金矿；随机六／八不相邻。开局先从一号位顺时针轮流抽取并放置十个海港，可约定年长者坐一号位，然后建初始村庄。开房前选择强盗与海盗同时使用或仅其中之一。每处非起始岛首次建村奖励一分。
- 新世界放完全部海港后，向所有玩家显示一次醒目的初始建设提示；确认前拦截棋盘操作，避免连续点击误放村庄。地图上方在初始建设期间持续标明村庄或道路／船阶段。聊天与重连不会重复弹出已确认的提示，再来一局重新提示；中途加入初始建设也会提示。
- 规则仅手动打开：进入航海家、切换版本或地图、开房、加入与重连均不自动弹出；关闭通用规则也不会接着弹出地图规则。开房页保留通用规则与地图规则入口，对局顶部并列“地图”“基础规则”“航海规则”三个双语入口，分别查看本图双语特殊规则及大图预览、通用玩法与费用、航海扩展规则；基础版在同一位置保留“基础规则”。窄屏规则入口独立成行，不挤占房间号、托管及离开按钮；顶部问号仍可查看规则。
- 船花费木材与羊毛各一张，每人独立拥有 15 艘船和 15 条路。村庄上限 5、城市上限 4；沿海初始村庄可配道路或船。海上不能建房、陆地内部不能造船，转换道路与航线必须经过自己的建筑。
- 旧船只有在自己建造阶段、开放航线末端且不受海盗封锁时可移动，每回合最多一艘；点击发光的船，再点新位置。新造船和封闭航线不能移动。
- 7 或骑士选择强盗/海盗；海盗只能进入海洋地块，封锁邻边造船和移船。多个可偷对象时点击发光的船，强盗仍点击发光的建筑。
- 金矿不是新资源卡：村庄选一张，城市选两张任意资源；按当前玩家起顺时针领取，受库存限制。等待非当前玩家领取时，房间不会跳过该选择；机器人及主动开启托管的玩家可自动领取。
- 轮到自己领取金矿资源时，显示紧凑金色通知、高亮回合栏和领取按钮，并响一次独立金矿提示音；点通知直接打开图标选牌栏。关闭选牌窗后提醒仍在，领取完毕自动消失并通知下一位。服从音效开关，重复状态、聊天、刷新重连不重播旧音效；暂停或托管时不催促手动领取。
- 金矿领取沿用交易的卡牌点选样式：上方五种资源图标每点一次添加一张，下方已选卡牌可逐张点掉，牌多自动换行。支持重复选择同种资源，数量未选够时不能确认，库存用尽或选满后不能再添加；重新打开从空白开始。银行库存变化时同步校正选择，确认后仍由服务器校验并发放。
- 扬帆出海、四岛群岛和穿越荒漠中，每位玩家每处外地的首次村庄额外获得 2 分；新世界改为 1 分，卡坦奇观改为外岛每个村庄 1 分。其他玩家抢先不影响奖励，升级城市不重复获得。建筑旁显示金色分数，玩家表单列显示已计入总分的登岛奖励；基础版不显示此列，未知海域没有登岛奖励。
- 最长商路计算船与道路，但路与船之间必须经自己的村庄或城市连接。玩家表保留已建道路和船只的独立总数，旁边另列最长连续商路长度，与最长商路计分一致。道路建设发展卡可造任意组合的两段道路/船。机器人会规划海上扩张、选择金矿资源、移动开放末端旧船和使用海盗；对接近本地图胜利分数的玩家减少交易。
- 电脑版（宽度大于 740px）玩家信息表放在地图与回合提示下方、奇观牌上方，右侧保留手牌、操作、银行与聊天。手机仍使用原来的侧栏顺序；调整窗口宽度只移动同一张表，头像互动、在线状态、聊天气泡及数据保持同步。
- 地图注册在 `catan-maps.js` 与 `catan-scenario-maps.js`，随机执行器在 `catan-random.js`，高级规则在 `catan-scenarios.js`。新地图使用同一套默认／随机开房控件；新增剧本必须明确分区、随机约束、初始限制和奖励规则，未声明随机规则的剧本会报错，不会直接全图乱洗。

## 五子棋与中国象棋

- 首页进入五子棋或中国象棋，选择机器人或好友。AI 可选入门、标准、进阶三级，先后手可选；好友模式创建房间后分享邀请链接或房间号。双方准备后房主开局，房主不固定先手。
- 两种游戏共用 `duel.html`，分别由 `?game=gomoku` 和 `?game=xiangqi` 进入。G 开头是五子棋房间，X 开头是象棋房间；新房间协议为 `/duel-ws`，必须更新并重启服务器，仅更新网页不能联机。
- 五子棋采用 15×15 自由规则：黑先，无禁手，五连或长连获胜，满盘无胜者则和棋。支持末手标记、胜利连线与手数开关。
- 象棋红先，校验马腿、象眼、河界、九宫、炮架、将帅照面与应将，选子后显示合法落点。将死或困毙均判负。
- 象棋采用休闲重复规则：单方长将导致三次重复则长将方判负，其他三次重复判和；无进攻子力或连续 120 半回合不吃子判和。未实现正式竞赛的复杂长捉仲裁，规则弹窗明确说明这一点。
- 五子棋机器人使用 Rapfi 0.43.01，象棋使用皮卡鱼 Pikafish 2026-09-06，均加载官方棋力模型。入门、标准、进阶的每步思考预算约为 0.2、1、3 秒，另需短暂启动时间；想挑战最强档请选择进阶。服务器独立进程计算，单线程、单任务队列，其他房间排队；手机不下载引擎或模型。悔棋、空位暂停、退出和服务器关闭会取消旧搜索，聊天和表情不会重新开始计算。
- 上传时必须保留 `vendor/engines` 整个目录及 `.gitattributes`。`npm install` 自动校验文件、拼接皮卡鱼的三段模型并实际测试两套引擎。Render 的系统库较旧时，会使用包内同版本源码在部署阶段编译皮卡鱼，首次构建稍长；不会访问外部模型下载网站。适用于 Windows x64 和 Linux x64（Render）；异常或不支持的平台才使用原 JavaScript AI，并记录服务器警告。详见 `AI-ENGINES.md`。
- 皮卡鱼程序是 GPLv3 开源，官方模型另有禁止未经许可商业使用的条件。本部署按仅朋友娱乐、不收费、不放广告使用；以后若商业化，先另获模型许可或更换模型。许可证、作者名单及固定版本源码归档均随包保留。
- 真人联机的悔棋、求和、换边与换边再来须对方同意。AI 模式悔棋可撤回自己最近一步及 AI 的回应。对局结束后通过“换边再来”重新开始；认输和离开都有确认。
- 默认头像为名字首字，可复用照片、相机与 emoji 头像；机器人随机取常见英文名，熟人池选择权重 40%。在线绿点、离线灰点，以及聊天气泡与原游戏一致。
- 刷新同一标签页自动重连并保留棋局，断线不代替真人落子；显式离开进行中的棋局视为认输。房间仍是内存保存，服务器重启或重新部署后需重新开房。
- `npm run test:ai` 验证真实引擎战术、合法走法、走棋历史、取消搜索、排队隔离、暂停补位、悔棋与重连；`node duel-ui-test.js` 使用 Playwright/Chrome 测试 320/390/1440 宽度下的操作、头像、消息、在线状态及首页。`npm run benchmark:ai` 运行新旧 AI 换先后手的小型对战，结果写入 `test-results/duel-ai-benchmark.json`，不作为等级分估计。
- 开源规则与搜索引擎均锁定版本并本地打包，见 `THIRD-PARTY.md`。上传时务必保留整个 `vendor` 目录与许可证。

## 房间保存

当前房间存在服务器内存中。服务器重启、重新部署或托管平台回收实例会清空房间；重连恢复适用于服务器持续运行期间。同一服务只运行一个实例。卡坦岛没有跨服务器存档或账号系统。

包含原德扑联机测试、卡坦岛规则测试，以及基础版和全部航海剧本默认／随机的完整机器人对战。`seafarers-expansion-test.js` 另检查前八图共 800 个随机种子的分区与数字约束、探索翻牌、金矿续行、荒漠奖励、隐藏牌堆及随机地图重连／重开。`catan-scenario-maps-test.js`、`catan-scenario-engine-test.js` 和 `catan-scenario-network-test.js` 检查后五图的库存、布局、礼物、布匹、战舰、奇观、海港轮放、隐藏牌堆及房间重连。`avatar-test.js` 另检查头像格式、大小限制、同步、重连及个人头像修改范围。

`social-test.js` 包含四个游戏的互动房间隔离、身份校验、频率限制和皮肤重连／重开测试。`node social-ui-test.js` 使用临时服务器和真实 Chrome 检查双浏览器同步、手机菜单、短长气泡、皮肤、机器人互动、键盘与减弱动画模式，以及旧德扑单机入口；可用 `TEST_ORIGIN` 环境变量指定另一个开发服务器。

`node --test room-control-test.js` 检查四游戏协商转让、断线接任、移除真人和机器人后暂停、本人重新加入、真人／机器人补位、状态继承、多空位、旧连接与旧目标失效，以及托管提醒和实际自动行动。`node room-control-ui-test.js` 检查四游戏双浏览器同意流程、移除真人／机器人双重确认、两步分别取消、房主或目标变化时旧确认失效、通过原加入表单重新进房、机器人补位和 320/390/1440px 的弹窗；倒计时边界用消息夹具加速，真实超时由服务端测试覆盖。

托管回归覆盖：默认超过超时门槛仍等待手动操作、四游戏房主开启后的提醒与自动行动、非房主无权修改、转让后权限交接、补位沿用房间设置、关闭时区分手动与超时托管、断线超过旧 30 秒门槛仍不代操作，以及手机开关和过期提醒处理。

房主可在开局后通过「房间管理」移除任何其他真人或机器人，保留空位和资产，补位前暂停。所有移除入口（含等待室移除机器人）都需要两步确认，显示目标名字，任一步均可取消；最后一步默认聚焦取消，且交换确认按钮位置以防连续双击。确认期间换房、转让房主或目标座位被替换时，旧确认失效。等待室移除请求还校验目标公开 ID，防止并发操作误删刚补入的机器人。

`node seafarers-ui-test.js` 检查十三张航海地图默认／随机预览、规则弹窗及手机/桌面显示，并保留前八图的初始造船、海盗偷取、非当前玩家领取金矿、移船和重连回归。另复现基础版和航海家在一号位初始建设前离开、重新开房、读完规则后直接建村庄的流程（含触屏点击），全程不刷新；房间和座位变化必须重新初始化建造状态。玩家表检查覆盖基础版与航海家在 320、390、1440 像素视口的最长路线、登岛分、奖项标记和多位数字，验证不溢出且与服务器一致。浏览器检查使用临时独立服务器，不修改已运行的真实房间。

`node catan-feedback-ui-test.js` 检查双浏览器定向／全员交易提醒、金矿领取顺序及提示、满额建设原因、手机横竖屏、静音与记忆、重连去重、胜利音效，并通过 OfflineAudioContext 渲染全部 24 种声音（含 6 种互动表情）、测量非静音和无削波。`catan-audio-test.js` 验证动作事件、隐藏发展卡不泄露、提醒对象和无音频 API 时的兼容降级。`game-audio-test.js` 验证共用音效控制，`social-ui-test.js` 检查四游戏双人互动音效、静音、音量与去重。
