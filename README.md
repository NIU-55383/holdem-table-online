# 桌游小馆 / Board Game Club

一个中英双语桌游网站，包含德州扑克、卡坦岛基础版与航海家十三张地图（默认／随机）、城市与骑士、五子棋、中国象棋、桥牌、真心话大冒险，以及百万美金。

## 统一规则页

- 七款游戏均有中英双语规则入口，开局前和对局中均可阅读。德州入口在德扑功能栏，棋类、桥牌、真心话大冒险和百万美金在顶部书本按钮，卡坦岛保留基础、航海和本图规则入口；不改变棋盘与牌桌外观。
- `game-rules.js` 与 `game-rules.css` 统一规则窗口的标题、章节、双语字号、手机滚动区和关闭按钮。德州、五子棋、象棋、真心话大冒险与百万美金内容位于 `game-rules-data.js`；桥牌和卡坦岛沿用已有内容及动态地图规则，接入同一个阅读器样式。德州“牌型大小”直接定位到规则页的十种牌型。
- 规则按实际引擎说明本馆变体，包括自由五子棋的长连获胜、象棋重复局面与 120 半回合无吃子，以及德州短额全下重新开放加注。以后新增游戏也必须接入该阅读器并提供等量的中英文内容，要求见 `AGENTS.md`。
- `npm run test:rules` 检查所有大厅游戏入口、双语内容及规则变体；`npm run test:rules-ui` 用 Chrome 检查全部游戏及航海/地图规则在桌面、手机横竖屏上的滚动、边界、关闭、焦点恢复，以及不会发送游戏操作。截图保存在忽略的 `test-results/`。

## 真心话大冒险 / Truth or Dare

- 首页第六个入口 `truth.html` 支持开局选择 2–8 人，分为单设备与好友联机；联机坐齐设定人数、全员准备后开始。可选真心话、大冒险或 Mixed，不分级（共 200 道真心话、100 道大冒险）。按回答者记录本局已抽题目，换题或跳过也计入；同一个人不会重复抽到，共同回答同时记入两人。记录随存档保留，题库用完可自定义题目。不设总题数，持续玩到主动退出，不自动结算或排名。
- 新局不掷骰。每轮随机抽不同的提问者和回答者；或选「回答者接着问」，首轮随机，此后上一轮回答者成为下一轮提问者，再随机选另一个回答者。跳过同样交接提问权，两人时交替互问。
- 两人真心话可选「共同回答」：直接显示同一题，各自完成或跳过，都回应后换下一题。两人轮流负责换题和自定义，任何一人回应后锁定本题。单设备提供两个具名按钮，联机只能确认自己。
- 每轮提问者有两次换题机会，另可输入 1–240 字自定义题目。开局设置每人整局跳过次数（0 / 1 / 2 / 3 / 5 / 10 / 不限），用尽不可继续跳过；断线、刷新、存档和换人不重置。只记录完成次数，不分胜负。V3 的旧限轮存档恢复时取消上限，保留题目进度、完成次数和跳过额度；V2 骰子存档继续兼容原规则。
- 不舒服时可随时停止游戏，涉及他人先征得同意，不要求喝酒。机器人及托管只自动跳过，不代替真人确认完成；跳过用尽时等待本人操作或房主换真人。旧 V2 骰子局存档继续使用旧规则，新局为 V3。
- 沿用统一头像、在线状态、六种头像互动与音效、完整中英规则和联机房间管理，包括房主五分钟断线保护、转让同意、移除双确认、空位暂停、补位和默认关闭的两分钟闲置托管。房间保存在服务器内存中。
- 前端 `truth.html`、`truth.css`、`truth.js`，题库 `truth-data.js`，引擎 `truth-engine.js` 与后端 `truth-server.js` 一起部署；联机入口 `/truth-ws`。本次玩法更新需重启服务器，旧局需重新创建，无需更改 Render 构建和启动命令。
- `npm run test:truth` 检查随机/接力/共同回答、换题与跳过额度、存档和联机权限，以及旧骰子存档兼容；`npm run test:truth-ui` 同时检查真心话新玩法及两款棋类的单设备、断网行棋、刷新、存档和手机布局。`npm run test:rules-ui` 检查统一规则窗口。

## 百万美金 / Millions of Dollars

- 界面沿用桥牌与小馆的浅灰绿背景、白色控件和深绿色按钮；大厅封面与保险柜使用同系平面插画。五种角色的原有识别色保留在插画、角色卡顶边和身份标签色条上，正文统一使用深色，确保浅底可读。
- 首页第七个入口 `million.html`，可选 2016 旧版（3–8 人）或 2024 新版（3–9 人），好友与机器人混合，使用独立房间码。参考站为 <https://million-dollar-9khy.onrender.com/>；本馆独立实现玩法和人物图形，不依赖参考站的服务、脚本或素材。
- 角色色值与参考站一致：司机 `#5ccf7f`、暴徒 `#ef6b6b`、恶棍 `#4fb3e8`、告密者 `#b48ef2`、谋士 `#e6b450`。秘密选角、混洗公开全部但藏起一张、谈判、绑定退出的付款提议、直接转账、威胁卡、告密、分赃和每轮回顾均由服务器处理。
- 三人每人两个不同角色；四人三种角色，五六人加入告密者，七八人加入谋士。每人初始 500 万，分赃者在结算后达到 2000 万可提前获胜，否则第八轮比较现金。金额单位为“万美金”，100 万 = $1M。
- 旧版按 [2016 Matagot 官方说明书](https://cdn.1j1ju.com/medias/2d/d3/e3-millions-of-dollars-rulebook.pdf)核对角色与结算。官方「角色不能连选」与本馆「暴徒不分赃」变体分开介绍；默认暴徒分赃，允许连选。两版均沿用本馆原有随机赃款数值与奖励配置，规则页说明实际配置，不当作十张原版实物牌的完整复刻。
- 新版按 [2024 Grail Games 官方说明书](https://www.grailgames.games/s/RulesRole-S_MoD_EN.pdf)实现独立流程：起始 $10M、每角色 $2M 保证金、依次声明身份、带头人发起投票且至少半数赞成、六种角色顺序结算、余款向上取整平分；轮末 $50M 或五轮后最富有者胜。下一轮最穷者带头。新增飞贼沿用既有角色插画风格；新版不使用旧版威胁卡和变体。
- 保证金短缺由储备补足，退款取回角色上的整笔保证金（包括补足部分）；现金不欠款。付款以 100 万为单位，没收保证金及分赃余数回储备；结算先平分再车费、恶棍取款、角色奖励，同玩家双角色之间不转账。
- 告密者唯一在场时必须点名一种公开的其他角色，不能主动跳过；所有淘汰处理后若独存，扣 300 万且不分赃，与其他角色一起存活时不罚款。这些细节直接写在角色卡及可点击的角色规则中。
- 隐藏身份不发给其他客户端；退出身份保密到本轮结束，在结算与历史中公开。旧版威胁卡从获得后的下一轮起使用，一张只看对手一个角色槽，情报只给使用者。旧版全员确认、新版至少半数赞成后开始抢劫；掉线不替玩家同意，等待重连或房主管理补位。
- 两版机器人均只读取本座位授权视图及公开聊天，按角色收益、撞身份风险和对手现金谈判。可开价退出、出钱收买、拒绝低价和选择点名或偷钱目标；发言可能如实声明或虚报身份，不对真人托管发送冒充玩家的聊天。默认交易思考时间仍为五秒。
- 使用统一头像、在线状态、互动音效、音量设置、中英规则、房主管理、五分钟继任保护、双确认移除、空位暂停和可选 120 秒托管。结算画面显示真实赢家，结果可在每轮回顾中重看。
- 一并部署 `million.html`、`million.css`、`million.js`、`million-art.svg`、`million-data.js`、`million-engine.js`、`million-2024.js`、`million-bot.js`、`million-server.js`、`room-archive.js` 和共享入口及规则改动。WebSocket 路径 `/million-ws`；无需新增依赖或更改 Render 命令。运行 `npm run test:million`、`npm run test:million-ui` 和 `npm run test:rules-ui`。

## 桥牌 / Bridge

- `bridge.html` 为四人定约桥牌；南北与东西固定搭档，可真人与机器人混合。开局前可以选位，与真人换位需对方同意；开局后座位与手牌保持稳定。
- 完整叫牌（Pass、加倍、再加倍）、首攻后公开明手、庄家控制明手、强制跟牌、将吃、收墩和结算。服务器使用 MIT 授权的 `@bridge-tools/core@0.3.1` 校验规则。其他玩家的手牌不会传给客户端，本副结束后可查看四家原始手牌与上一墩。
- 采用每副独立的复式定约计分、标准发牌人与 16 副局况循环；每场选 4 / 8 / 16 副，比较累计净分。不使用橡皮桥累计局分，不换算 IMP / matchpoints。房主在每副结算后手动开始下一副。
- 点击本副结算或历史计分表的分数，可查看中英双语计算明细：定约、实际赢墩、庄家方局况、定约墩分、奖励、超墩或宕约罚分。例如 2NT 恰好完成得 120 = 70 定约墩分 + 50 部分定约奖励。`bridge-score.js` 仅解释服务器已经结算的分数，不改动对局；测试逐项核对全部 23,520 种定约、座位、局况与赢墩组合。
- 机器人使用自然叫牌、搭档点力／套长推断、进局邀请、强 2♣ 与等待应叫、争叫和技术性加倍；无将后的花色应叫为自然叫，不混用未说明的转移叫。区分开叫前不叫与防守方不争叫，不把得到支持后的再叫误认成长套；两门高花优先较长的一门，无将开叫后按搭档自然应叫寻找 5–3 配合。基础叫牌与首攻参考 [ACBL](https://www.acbl.org/learn/)。
- 出牌记忆公开历史和缺门，并考虑叫牌透露的点力、套长和均型。中盘使用 24 个候选分布并推演本墩剩余行动；最后五墩使用 16 个候选分布及有节点上限的深度搜索，合并等价牌并缓存残局。按定约得分比较路线，保留隐藏风格。策略只接收自己的牌、公开明手和公开记录，绝不读取对手真实手牌。
- `bridge-bot-worker.js` 用一个后台工作线程顺序处理各房间的搜索，避免占用网络主线程。暂停、退出、换局和托管变化会取消旧任务；结果返回后再次校验局面与行动权限。
- 每位机器人在服务器端固定一种隐藏风格，影响边缘叫牌、首攻和风险偏好。同桌机器人优先分配不同风格，换座、重连和下一副不改变；替补机器人重新分配。风格不进入房间快照，不显示在名字、头像或界面中。
- `node bridge-ai-benchmark.js 48` 在相同发牌、固定定约下，与早期简单策略换边对照；可追加旧版 `bridge-bot.js` 文件路径，与指定版本对照。2026-11-12 对升级前机器人的 48 组 / 96 局测试：26 组领先、10 组持平、12 组落后，净多拿 28 墩。这是可复现的出牌策略回归，不代表真人竞技等级。
- 包含站内完整中英双语规则、手机排版、选牌后出牌确认、叫牌记录、计分表、聊天、头像与六种互动音效、静音及音量设置。所有素材随仓库提供，不请求外部图片或音频。
- 定约成立后，桌面中央持续显示本局将牌或无将 NT；四张出牌围绕提示排列。侧栏定约位于叫牌记录上方，桌面与手机共用同一顺序。
- 与其他游戏共用房主管理、转让同意、离线继任、移除双确认、空位暂停、重新补位和默认关闭的两分钟托管。明手由庄家操作时，只给庄家计时。
- `npm run test:bridge` 检查规则与房间适配；`npm run test:bridge-ui` 运行 Chrome 桌面／手机浏览器回归（需 Playwright 与 Chrome）。桥牌 WebSocket 入口为 `/bridge-ws`，部署不需更改 Render 配置。

- 桥牌仅保留中英双语规则页，不再提供教学模式、练习牌、答题或出牌指导。教学模块及专用测试已删除，旧教学文件地址返回 404，旧教学协议不再创建或推进练习；普通对局、机器人、上一墩和结算看牌不受影响。

## 统一玩家界面

- 所有游戏都可点击其他玩家或机器人的头像，发送送花、泼水、比心、鼓掌、干杯、好运六种互动。自己和同房玩家都能看到约 2.4 秒的小表情；不影响游戏回合、AI 思考或牌局记录。自己的头像仍打开头像编辑器。每位玩家发送间隔至少 1.2 秒，重连不重播旧互动。
- 聊天气泡按文字长短收缩，长消息限制宽度与高度，不再占满玩家信息整行；完整内容保留在聊天记录中。
- 玩家头像可上传照片、主动点击拍照，或输入一个 emoji；未设置时显示名字首字。在名字旁边或房间内点击自己的头像即可更换，取消不会保存修改。
- 照片在本机居中裁成 128 × 128 的小头像并重新编码为 JPEG（去除原图元数据）后，才同步给房间中的其他玩家；不会上传原图。支持 10 MB 以内的 JPG、PNG 和 WebP。手机拍照取决于设备和浏览器支持，电脑通常打开文件选择器。
- 头像偏好保存在当前浏览器，同一网址下的卡坦岛和德扑共用；服务器持续运行时，重连可恢复房间头像。机器人入座时随机使用统一画风的表情图案或名字首字，不再使用固定人物肖像。
- 卡坦岛、德扑及后续新增游戏共用 `game-ui.js`、`game-ui.css` 的头像状态点：左下角，在线绿色，离线灰色。
- 所有游戏的送花、泼水、比心、鼓掌、干杯和好运都有对应短音效，由 `game-audio.js` 本地合成。收到确认的互动时播放一次，静音仍保留表情；菜单喇叭可开关声音，卡坦岛同时沿用现有音效开关与音量。首次点击、触摸或键盘操作解锁声音，后台与未解锁时不补播，重复事件不重播。新增游戏须在 `game-ui.js` 前加载 `game-audio.js`。
- 状态由真实连接决定，不随是否轮到自己、弃牌或托管而改变；正常运行的机器人和本地单人玩家按在线显示。

## 房主与中途补位

- 德扑、卡坦岛（含航海家）、桥牌、五子棋、中国象棋、真心话大冒险、百万美金共用「房间管理 / Manage room」入口，位于原房间工具栏，图标为两个人。
- 房主可以向在线真人提出转让；对方同意后才生效。其他玩家也可申请成为房主，由现任房主同意或拒绝。
- 房主断线后保留权限五分钟，期间刷新或重连不会换房主；重新在线后取消倒计时，下次断线重新计满五分钟。连续离线满五分钟才按约定号位顺时针寻找下一位在线真人接任，跳过机器人和离线玩家。主动退出立即交接，手动转让仍需双方同意；接任完成后旧房主回来不会自动取回权限。突然断网须先经心跳检测确认，再开始五分钟计时。
- 开局后，房主可移除其他玩家（含机器人），需要再次确认。位置保留为空位，整局暂停；机器人、游戏操作和自动下一手都停止，但聊天、头像互动、管理仍可使用。
- 房主可为指定空位补机器人；新的真人通过房间号加入会自动补第一个空位。接手者继承该座位的棋局、手牌、资源或筹码，不重新开局。多个空位必须全部补齐才继续。
- 被移出者回到加入界面，旧连接的房间权限失效，不会自动抢回座位；本人仍可重新输入房间号加入，前提是仍有空位。本网站沿用房间号加入，不另设密码。
- 所有游戏默认关闭超时托管。只有当前房主能在「房间管理」勾选「全员两分钟未操作时自动托管」，其他玩家可查看、不能修改。开启后，需要作出决定的在线真人 120 秒未操作才托管，最后 20 秒提醒。房主转让、重连及补位沿用房间设置；补位者不继承旧人的托管状态。关闭时清除全员计时并停止因超时触发的托管，但不打断玩家主动开启的托管。

- 所有服务端使用 `room-control.js` 校验当前成员和房主权限，前端通过共享 `BoardGameUI.mountRoomControl` 显示控制和提醒。此功能需要同时更新前后端并重启服务器。
- 游戏结束提示使用真实赢家姓名和中英双语，例如 `Laura 胜利 / Laura wins`。
- 新增游戏时遵循 `AGENTS.md` 中的共享 UI 规范。

## 房间保存

当前活动房间存在服务器内存中。服务器重启、重新部署或托管平台回收实例会清空房间；重连恢复适用于服务器持续运行期间。同一服务只运行一个实例。没有账号或云存档系统；七款游戏可下载文件存档，服务器重启后仍可导入恢复，不增加托管费用。

- 房主打开「房间管理 → 保存」，可下载当前进度而不暂停、不退出、不移除玩家。单设备游戏也有独立的保存按钮。存档导入时仍会创建新房间并重新选座。
- 「保存并退出」先暂停并下载 `.json` 存档，确认文件已下载后再退出。此时原房间关闭，所有真人、机器人及旧身份解绑；取消则继续原局。两分钟未确认自动取消暂停，下载的文件仍可保留。
- 下次在同一游戏的开房页选择「导入存档」，生成新的房间码。导入者和朋友都在选座窗中认领位置，继承该位置的牌、棋子、资产、当前回合与成绩，选座预览不公开暗牌。入座后不可再换座，第一位入座者成为房主；空位可补机器人，坐齐后房主点击「继续对局」。
- 文件包含完整暗牌，未加密，不是防作弊的比赛记录，仅交给可信任的人。支持当前第 1 版、最多 2 MB 的存档；版本不符、棋谱非法或结构损坏会拒绝导入，原对局不受影响。不要手工编辑存档。
- 保存牌堆、手牌、建筑、资源、分数、骰子/回合进度、桥牌牌号及历副成绩、卡坦岛统计。象棋通过合法棋谱重建局面与重复历史。旧登录凭证、头像、聊天、房主身份、托管状态和未完成的交易同意不保留。真心话、五子棋和象棋单设备局也可下载，之后导入成可选座的在线房间。
- 存档实现由 `room-archive.js`、`game-archives.js` 和共享房间管理组成。新增游戏需提供进度适配、隐私校验及浏览器往返测试。运行 `npm run test:archives` 和 `npm run test:archives-ui`。

卡坦岛在同一网站、同一浏览器中按房间保存最近 24 小时的恢复凭证（最多 8 个）。关闭标签页后重新输入原房间码，或点击「返回对局」，可恢复原座位与资产；不会仅凭同名认领座位。当前标签页仍保留独立身份，不会因另开页面自动入座。被移出或主动离开会清除返回入口，被移出的玩家须由房主空出座位后主动加入。房主五分钟保护和到期接任规则不变。清除网站数据、换设备或服务器重启不属于这项恢复能力；对局失效时移除旧地图并提示，不伪装成恢复成功。

`npm run test:catan-reconnect-ui` 使用独立测试服务器检查关页重开、满房恢复、原资产与隐藏牌、房主保护及接任、同名冒认拒绝、离线移除与主动补位、多标签连接、过期房间和桌面／手机返回入口。

`catan-extension-test.js` 检查基础版 5–6 人的地形、数字序列、港口、资源与发展卡库存、配对回合、交易限制、发展卡时机、七点弃牌、双方胜利、完整机器人对局及六人房间换座／补位／重连／重开。`node catan-extension-ui-test.js` 检查扩展预览、人数切换、配对提示、银行交易和手机／桌面布局。

`social-test.js` 包含四个游戏的互动房间隔离、身份校验、频率限制和皮肤重连／重开测试。`node social-ui-test.js` 使用临时服务器和真实 Chrome 检查双浏览器同步、手机菜单、短长气泡、皮肤、机器人互动、键盘与减弱动画模式，以及旧德扑单机入口；可用 `TEST_ORIGIN` 环境变量指定另一个开发服务器。

`node --test room-control-test.js` 检查五款游戏的协商转让、断线保护与到期接任、移除真人和机器人后暂停、本人重新加入、真人／机器人补位、状态继承、多空位、旧连接与旧目标失效，以及托管提醒和实际自动行动。五分钟边界用确定性时钟检查，联机接任测试通过 `ROOM_HOST_GRACE_MS` 缩短等待，部署时不设置此测试变量。`node room-control-ui-test.js` 检查四游戏双浏览器刷新保留房主、同意流程、移除真人／机器人双重确认、两步分别取消、房主或目标变化时旧确认失效、通过原加入表单重新进房、机器人补位和 320/390/1440px 的弹窗；倒计时边界用消息夹具加速，真实超时由服务端测试覆盖。

`node catan-score-ui-test.js` 检查卡坦岛的“普通得分 + 加分卡及世外部落标记”显示、没有加分时省略加号、对手隐藏信息、结算公开与手机布局。

`node --test catan-stats-test.js` 检查赛后统计的隐藏信息隔离、获胜动作、逐回合与配对回合、骰子、资源口径、建设次数、抢夺与海盗袭击次数、全部航海地图和基础版 3–6 人完整对局。`npm run test:catan-stats-ui` 在双浏览器中检查五张图、六个号位、320/390/1440px 与手机横屏、键盘、表格、重连、重开、抢夺零值和旧局缺失数据，以及关闭后不因聊天重复弹窗。

托管回归覆盖：默认超过超时门槛仍等待手动操作、四游戏房主开启后的提醒与自动行动、非房主无权修改、转让后权限交接、补位沿用房间设置、关闭时区分手动与超时托管、断线超过旧 30 秒门槛仍不代操作，以及手机开关和过期提醒处理。

房主可在开局后通过「房间管理」移除任何其他真人或机器人，保留空位和资产，补位前暂停。所有移除入口（含等待室移除机器人）都需要两步确认，显示目标名字，任一步均可取消；最后一步默认聚焦取消，且交换确认按钮位置以防连续双击。确认期间换房、转让房主或目标座位被替换时，旧确认失效。等待室移除请求还校验目标公开 ID，防止并发操作误删刚补入的机器人。

`node seafarers-ui-test.js` 检查十三张航海地图默认／随机预览、规则弹窗及手机/桌面显示，并保留前八图的初始造船、海盗偷取、非当前玩家领取金矿、移船和重连回归。另复现基础版和航海家在一号位初始建设前离开、重新开房、读完规则后直接建村庄的流程（含触屏点击），全程不刷新；房间和座位变化必须重新初始化建造状态。玩家表检查覆盖基础版与航海家在 320、390、1440 像素视口的最长路线、登岛分、奖项标记和多位数字，验证不溢出且与服务器一致。浏览器检查使用临时独立服务器，不修改已运行的真实房间。

`node catan-feedback-ui-test.js` 检查双浏览器定向／全员交易提醒、金矿领取顺序及提示、满额建设原因、手机横竖屏、静音与记忆、重连去重、胜利音效，并通过 OfflineAudioContext 渲染全部 24 种声音（含 6 种互动表情）、测量非静音和无削波。`catan-audio-test.js` 验证动作事件、隐藏发展卡不泄露、提醒对象和无音频 API 时的兼容降级。`game-audio-test.js` 验证共用音效控制，`social-ui-test.js` 检查四游戏双人互动音效、静音、音量与去重。

头像浏览器检查同样需要 Playwright 与 Chrome。在 PowerShell 中先运行 `$env:AVATAR_UI = '1'`，再运行 `node --test avatar-test.js`，可验证上传压缩、拍照文件选择入口、emoji、撤销、跨游戏复用和手机布局。它不会访问真实摄像头；真机拍照仍需在手机上检查。
